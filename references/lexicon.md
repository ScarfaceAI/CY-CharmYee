# 词库与纠错记忆

本功能维护词汇来源和校对记录，供[疑点清单](suspects.md)查询。纠错记忆只供提示，不能自动替换机器原稿或校对稿，也不向识别引擎传热词。成语表通过已有的 `numbers.apply(extra_exceptions=...)` 保护展示文字中的固定说法，数字规则、转换阈值和豆包识别流程保持原样。

## 数据放在哪里

| 数据 | 位置 | 是否随源码和安装包分发 |
|---|---|---|
| THUOCL 与 jieba 词典数据的固定版本、类别、大小、SHA-256、许可和地址 | `assets/lexicons.json` | 是，仅清单 |
| 领域词表和上游许可文件 | 模型根目录的 `lexicons/thuocl-<提交哈希>/` | 否，按需下载，多个工作区共用 |
| 通用词典数据和上游许可文件 | 模型根目录的 `lexicons/jieba-<提交哈希>/` | 否，按需下载，多个工作区共用 |
| 个人词条、来源、校对事件、计数依据、撤销标记 | 工作区 `.local/lexicon/state.json` | 否，属于个人数据 |
| 导入词表的原样副本 | 工作区 `.local/lexicon/imports/<文件哈希>.txt` | 否，属于个人数据 |
| 校对稿与版本快照 | 原有 `runs/<任务>/` 目录 | 否，沿用现有登记机制 |
| 本篇展示使用的成语例外 | `result.json` 的 `display.lexicon_exceptions` | 否，属于任务数据 |

模型根目录沿用 `models.py` 的选择顺序：`CY_MODEL_DIR`、本机设置中的 `model_dir`、默认 `%LOCALAPPDATA%/cy-charmyee/models`。无需为每个工作区另下词表。

个人词库、导入副本、纠错记忆、账号、话题、稿件及知识库标题只保存在本机，不上传、不提交到源码、不加入安装包。比对和学习在本机完成，不调用识别服务；需要公开词库时可能启动后台下载，下载只请求清单中的公开文件，不发送个人数据。备份工作区时可一并备份 `.local/lexicon`。

## 公开词库

使用[清华 THUOCL](https://github.com/thunlp/THUOCL/tree/a30ce79d895d01ab5132a5c74c29703ff7efb4cc)，固定提交 `a30ce79d895d01ab5132a5c74c29703ff7efb4cc`，MIT 许可全文见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。它是较早的领域词表，覆盖信息技术、财经、地名、饮食、成语等，不是通用词表。疑点层另用 [jieba 的通用词典数据](https://github.com/fxsjy/jieba/blob/1e20c89b66f56c9301b0feed211733ffaa1bd72a/jieba/dict.txt)，固定 `v0.42.1` 对应提交 `1e20c89b66f56c9301b0feed211733ffaa1bd72a`，同为 MIT，仅下载约 5 MB 的词典及许可，不安装 jieba 包。缺词不能证明错误，也不能据此判断新产品或新术语不存在。

清单独立放在 `assets/lexicons.json`，因为类别、词频和来源版本不属于模型推理配置。下载共用 `models.py` 的后台进程、进程锁、断点续传、备用源切换、大小与哈希检查及导入暂存机制。各文件提供固定提交的 GitHub Raw 地址和 jsDelivr 备用地址，必须通过同一 SHA-256。

首次展示本地转写、登记校对稿、补学或查询需要公开词库时，若尚未下载，会自动启动后台下载。本次不等待网络，照常降级处理，`tell_user` 说明“公开词库正在后台下载，下次起生效”。已有下载进程时不重复启动；进程身份与模型下载一样核对。后台失败或意外中断后才提示手动导入，也可用 `lexicon download` 显式重试。失败状态不会在每次使用时自动重复下载。`lexicon status` 仅查看状态，不启动下载。

以下命令均接在已安装 Skill 的 `scripts/invoke.ps1` 后执行：

```text
lexicon status
lexicon download
lexicon import-public "<包含 LICENSE 与 data 子目录的文件夹>"
lexicon lookup 字节
lexicon lookup 李白 --category lishimingren
lexicon status --dictionary jieba
lexicon download --dictionary jieba
lexicon import-public "<包含 LICENSE 与 jieba/dict.txt 的文件夹>" --dictionary jieba
```

不传 `--dictionary` 时仍操作 THUOCL；`status`、`download`、`import-public` 可用 `--dictionary jieba` 选择通用词典。疑点检查首次需要通用词表时自动启动后台下载，本次跳过同音检查，其他三类照常；就绪后用 `suspects <任务 ID>` 重算。失败不自动反复重试，显式 `download` 可重试，`status` 只读状态。

手动导入保留官方结构：THUOCL 的根目录为 `LICENSE`，`data/` 下为清单中的 11 个原始 TXT 文件；jieba 为根目录的 `LICENSE` 与 `jieba/dict.txt`。全部校验通过后才安装；不要重存词表，以免换行或编码改变哈希。公开词表不通过个人词表的 `lexicon import` 安装。

| 类别标识 | 内容 |
|---|---|
| `IT` | 信息技术 |
| `animal` | 动物 |
| `caijing` | 财经 |
| `car` | 汽车 |
| `chengyu` | 成语 |
| `diming` | 地名 |
| `food` | 饮食 |
| `law` | 法律 |
| `lishimingren` | 历史名人 |
| `medical` | 医学 |
| `poem` | 诗词 |

词频是上游的文档频率 `DF`，即包含该词的文档数，不是当前互联网热度。各类统计语料不同，跨类查询返回各自数值及可用最大值，不相加。读取时去掉字段两侧空白、跳过空行，同类重复词取较高的有效词频；原文件保持原样。上游有 4 条词频为空或带非数字字符的记录，保留词条，词频返回 `null`，不猜测数字。

词库缺失或下载未完成时，公开词查询返回未就绪，仍可使用个人词库和记录校对改动；本地识别继续使用内置展示例外。已有文件校验不通过时会按缺失文件自动补下；本次不使用未校验的内容。下载耗时与网络异常不阻塞 `run`。

`display.lexicon_exceptions` 记录是否使用、提交版本、成语文件 SHA-256 和本篇实际匹配到的成语。即使匹配词数为零，只要使用了已就绪词表，也记录版本。未就绪时记录 `used: false`、`revision: null`、空词表。对已有结果重算时沿用这份例外快照，后来下载、升级或移走词库不会改变相同记录的结果；旧结果没有此字段时，首次重算才选择当前词库并记录。回执中的下载提示按当前进度生成，词库就绪后说明旧稿仍沿用未使用公开词库的快照，避免反复显示过时的下载提示。

## 个人词库

```text
lexicon add 承意 --note "产品名" --source "任务 dy-example 的第 1 条校对"
lexicon add WorkBuddy --source "视频标题或作品链接"
lexicon list
lexicon remove WorkBuddy
lexicon import "<UTF-8 词表.txt>"
```

Agent 遇到有依据的明显专有名词可以直接添加，并用 `--source` 写明来自哪次校对、哪条视频。普通词不要反复加入个人词库。词条说明也参与相关性查询，适合补充所属话题。

导入格式为每行一个词，可用制表符附带其他列；当前仅使用第一列，空行和以 `#` 开头的行忽略。先保存完整原文件副本，再从副本读取词条，记录来源文件名、哈希和导入时间。之后外部文件被移动或修改不会影响词表。

`remove` 移除个人词条，并阻止自动学习再次加回；显式 `add` 或再次导入可恢复。公开词表不受影响。

## 校对记忆与补学

登记 `review` 时，先完成原有校验、版本快照、`source_basis` 和状态流转，再学习新增记录。口播 `spoken` 不进入纠错学习。返回的 `tell_user` 说明本次新增几处改动，列出前 5 处“原文 → 改后”，明确已记入记忆。记忆写入失败时，校对登记仍成功，并提示用 `lexicon learn` 补建。

```text
lexicon learn
lexicon memories
lexicon forget Workbody
lexicon forget Workbody --delete
```

`learn` 扫描 `runs/` 中当前及历史已登记的校对版本；优先读登记时的哈希快照，没有快照的旧稿必须与登记哈希一致。依据改变或哈希不符的稿件列为未学习。每份校对以“任务 ID、作品 ID、校对稿 SHA-256”去重。豆包原稿照常学习并保留原来的引擎标识，不伪装成本地模型经验。

比对优先读取 `result.json` 的 `raw_text`，旧稿使用 `text`。比较前消除标点、空白与等值数字写法差异，包括 `六一六／616`、`十二／12`、百分数和小数。这只服务于比较，不修改正文或展示阈值。展示产生的数字与间距变化不记为识别纠错。

比对得到的差异先扩展到词边界再记忆。切分同时使用公开词库、个人词库和本次校对学到的词，采用正向、反向最大匹配，优先选未知字较少、词数较少的结果。少量内置语法边界用于分开未收录的片段；同一词内相邻改动合并。英文保留完整词，空格与标点仍作为英文词边界。比如记录 `元气 → 元器`、`原接器 → 元接器`、`激发 → 击发`、`阿豌豆 → 阿班豆`、`扎啤 → 扎皮`，不再只记其中一个汉字。`对之 → 对峙和` 分为词语纠正 `对之 → 对峙` 与单独插入 `和`；词内补字则可形成 `阿托维亚 → 阿托维尼亚`。

每处改动保留完整的词级原文、改后、两边的前后文及位置，附任务、作品、校对哈希、账号、标题、简介、话题、引擎、登记时间和展示记录。相同词级原文与改后合并，次数按实际出现处数计算。一份稿件改正两次相同错误，次数为 2；重复扫描仍为 2。新增和删除也留记录，空的一侧显示为“（空）”或“（删除）”。这些是文本差异证据，不等于已判断语义或专名正确。

每条记录带 `type`、中文 `type_label`、`can_suggest`、`requires_context` 和中文 `context_reason`。`can_suggest` 决定能否提示；只有可提示记录才需要判断场景限制。`memories` 列出全部记录；`query` 默认只返回可用于提示且与本次视频相关的记录。

| 类型 | 判定与例子 | 能否用于提示 |
|---|---|---|
| 专名或术语 | 改后是个人词、学到的词或公开人名地名，如 `阿豌豆 → 阿班豆` | 能；含汉字原文默认限场景 |
| 词语或短语 | 两侧都至少有 2 个汉字，如 `激发 → 击发` | 能；默认限场景 |
| 英文词 | 两侧都是完整英文词，如 `foobar → foobaz` | 能 |
| 方言 | 改后含明确方言字，如 `冰斗该 → 边度嘅`、`该 → 嘅` | 能；默认限场景 |
| 虚词或语气词 | 一侧仅由虚词、代词或语气词组成，如 `的 → 地`、`Sure → 啊` | 不能 |
| 纯插入、纯删除 | 词边界扩展后仍有空的一侧，如插入 `你`、`哦`、`和` 或删除 `哈` | 不能 |
| 单字 | 非方言的单个汉字纠正，如 `配 → 加` | 不能 |
| 其他 | 不满足以上提示条件的改动 | 不能 |

纯插入、纯删除和虚词优先归类；普通单字不能仅因出现在词库中就成为提示。方言单字可以保留提示资格，场景限制和推广规则与其他含汉字原文的记忆一致。上述记录均不会触发自动替换。当前词级状态使用版本 2；尚未投入使用的旧版字符级测试状态不迁移，可在新的测试工作区重新学习。

自动学词采用保守规则：完整英文缩写／产品名、公开词库中的人名地名和较长专业术语、有明确命名语境的词、部分术语后缀。只有与校对改动位置相交的词才从稿件加入。普通字词纠正会记入纠错记忆，但不因此变成个人术语；无法可靠识别的中文专名可用 `add` 补充。

`learn` 还读取工作区配置的 `vault_root`。未设置时不访问知识库；设置后只读 Markdown 文件名及前 30 行中的首个一级标题，按同一术语规则学习整个标题，不学习正文，不改知识库。长句标题和普通标题不直接收录。校对登记本身不扫描知识库，这项学习只在显式 `lexicon learn` 中执行。

默认 `forget` 否定这个完整词级原文的记忆，保留证据；`--delete` 从可查询记忆中删除，保留防止重复学习恢复的标记。例如 `lexicon forget 元气` 只作用于原文为 `元气` 的记忆，不影响其他带有 `气` 字的词。原稿、校对稿和版本快照不改。否定记录仍可通过 `memories` 查看，`can_suggest` 为假，相关性查询不再推荐；个人词条若也不需要，另用 `remove` 移除。

## 查询接口与权重

```text
lexicon query --title "AI 智能体" --tag AI --description "产品比较" --account "科技账号"
```

供下一步调用的 Python 接口位于 `douyin_text.lexicon`：

| 接口 | 返回内容 |
|---|---|
| `PublicLexicon().lookup(word, categories=None)` | 词是否存在、词频、类别、就绪状态 |
| `PublicLexicon().category(category)` | 指定类别的词与词频 |
| `PublicLexicon().candidates(text='', categories=..., limit=50)` | 人名／地名等候选，按频率排序，可指定类别和字面筛选 |
| `PublicLexicon().idioms()` | 成语表 |
| `compare(raw, reviewed, public=..., words=...)` | 词级改动、类型、提示资格与未改片段，包含原始位置 |
| `memories(root)` | 全部纠错记忆、类型、提示资格、次数、最近时间、账号、话题、否定记录 |
| `query(context, root, at=None, limit=50)` | 相关个人词、学到的词及记忆，按分数降序及稳定次序排序 |
| `memory_scope(original, replacement, kind, occurrences=())` | 根据原文、类型和确认记录判断提示范围，无读写的纯函数 |
| `memory_weight(memory, context, at)` | 无读写、无隐式当前时间的纯权重函数 |

直接构造 `PublicLexicon()` 只读取本机已有词库；使用 `PublicLexicon(auto_download=True)` 或 `ensure_public()` 可按需启动后台准备。命令行查询、学习和展示接入采用后者，状态检查保持只读。

上下文接受 `title`、`description`、`account`、`tags`，兼容来源中的 `author`；标题和简介中的 `#话题` 自动提取。相同账号加 3 分，每个相同话题加 2 分，标题与简介的二字组合相似度贡献 0～2 分，至少两个字符的完整词命中上下文加 4 分。没有相关证据的词或记忆不返回。

含汉字原文的可提示记忆默认限场景：必须命中至少一条确认来源的同账号或同话题。仅标题相似或字面出现不能越过这个限制。例如 `激发 → 击发`、`扎啤 → 扎皮`、`对之 → 对峙`、`阿豌豆 → 阿班豆`、`原接器 → 元接器`、`从养鱼走随 → 同饮宇宙水`、`元气 → 元器`，第一次确认后都不会在其他账号、其他话题里提示。公开人名地名也适用这条规则。

同一组“原文 → 改后”在至少两个不同账号得到确认，或在至少两组不同且非空的话题记录里得到确认后，才推广为全局提示。多个话题挂在同一条视频上只算一组话题证据；同账号、同组话题里的重复改正只增加次数，不推广。不同稿件的话题组合必须有变化，空账号或空话题不算额外场景。另一场景出现原文却没有修改，是反证，不是确认，也不能用于推广。

`Workbody → WorkBuddy`、`ttk → TTK` 等英文或字母专名保持全局提示。`q 克劳 → QClaw` 也保留这一例外：改后是已收录的英文专名，原文以与其前缀一致的拉丁字母开头、后接中文音译。纯中文原文改成英文专名，例如 `克劳 → QClaw`，仍默认限场景。全局提示只是解除同账号、同话题的硬性限制，查询仍需有标题、简介、词语等相关证据。

范围由已登记的确认记录计算；`compare` 尚无历史确认时返回默认范围，`memories` 和 `query` 返回累计证据对应的范围及中文原因。公开词频仍原样保留为来源信息，但不再参与“是否限场景”的判定，也不再单独硬编码 `元气`。固定版本中缺少 `激发`、`扎啤`、`元气`、`对峙`、`元器`、`击发` 等词，不能据此推断它们的通用词属性。

纠错权重对每次确认累加：`（0.25 + 0.75 × 0.5^(距今天数 / 180)）×（1 + 相关分）`。多次、较近及相关场景的确认权重更高。原片段出现在已登记稿件的未改部分时，记录该场景的反证；查询与反证相关才降低权重，除以 `1 + 各相关反证的（1 + 相关分）之和`。显式否定再乘 0.1，且不进入常规推荐。保留全部事件后计算反证，先扫描未改稿、后扫描纠错稿也能得到同样结果。

权重只决定提示顺序，不能当作改稿授权。每项仍带来源，应根据本次音视频、上下文及校对依据决定是否使用。
