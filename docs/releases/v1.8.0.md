# 承意 · CY-CharmYee 1.8.0

2026-11-16 · Windows

## 中文

本版新增校对版字幕：校对时改对的人名、数字和作品名可以直接进入 SRT 字幕，时间轴沿用识别时的分句，不必再在剪辑软件里改第二遍。竖屏短视频还可以按字数切成短行、去掉首尾标点。

### 功能与变化

- **校对版字幕。** `export-srt <任务> --reviewed` 把已登记的校对稿按字对齐回已存的识别分句，更正进入字幕，时间轴沿用原分句，不重新调用语音识别。新字幕按内容哈希另存到任务交付目录，不覆盖旧文件，也不改变任务状态。
- **竖屏短行。** `--max-chars`（4–80，标点不计）把长句拆成短行，优先在标点、引号书名号、语气词之后或常见起词字之前断开；英文单词和数字不拆开，100,000 这类千分位写法也保持完整。拆分后的时间按字数比例估算。`--strip-end-punct` 去掉每条首尾的逗号、句号等，保留问号、感叹号和引号。两项也可用于机器原文字幕。
- **只用有效的校对稿。** 未登记、登记后又修改、文件缺失、识别依据已变化，或校对稿与识别原文只有标点的条目单独列出原因，不用机器原文顶替，同批其他条目照常导出。校对稿与识别原文能对上的字不足 60% 时（多为改写稿或登记错了条目），拒绝沿用时间轴。
- **标出值得抽查的字幕。** 结果中的 `check_cues` 列出大部分文字被更正、读速超过每秒 12 字，或只能按字数硬拆的字幕，方便交付前逐条检查。
- 不带新参数的 `export-srt` 输出与以前逐字节相同。

### 升级与兼容

已安装承意 1.6.0 及以后的用户可通过现有更新入口更新，使用 `update --apply` 安装。新参数都是可选的；安装参数、配置、凭据和任务数据格式没有变化，无需迁移。已有任务只要保存了识别分句时间，按现有流程登记校对稿后即可导出校对版字幕。

旧 `dyb-*` 或 `douyin-brain` 品牌版本首次迁移到承意仍须运行新安装器，不能用旧品牌更新器直接跨产品升级。详见[维护与发布指南中的已有用户升级说明](../RELEASING.md#已有用户如何升级)和[运行指南](../../references/runtime.md)。

### 验证范围

发布前本地完整行为测试 **261 项通过，耗时 179.935 秒**（Python 3.12，锁定依赖）。功能开发时的端到端试跑使用一段 35 秒解说样例和模拟的豆包识别结果，经真实命令行导出：8 处人名、作品名、型号、数字和术语更正全部进入字幕，时间轴不变，匹配度 0.92；按每行 14 字切成 19 条，仅 1 处按字数硬拆并已标出。约 1.5 万字的对齐耗时约 3.5 秒。

功能合并后，自动代码审查指出千分位数字会被拆开、单条只有标点会中断整批导出两个问题，已在本版修复并补充回归测试。GitHub CI、标签、源码提交和公开安装包校验以本 Release 的公开验证附录为准。

本轮没有发起真实豆包语音请求，没有用真实视频跑完整流程，也没有检查字幕导入剪映等剪辑软件后的显示效果；拆分短行的时间是按字数估算的。各 Agent 宿主中的实际会话行为同样未验收。

## English

Version 1.8.0 adds reviewed subtitles. Names, numbers and titles corrected during review can go straight into SRT subtitles with the original recognition timing, so they no longer need a second round of fixes in an editor. Vertical videos can also use short lines without edge punctuation.

### Features and changes

- **Reviewed subtitles.** `export-srt <task> --reviewed` aligns the registered review text with the stored recognition segments, so corrections reach the subtitles while the original segment timing is kept, without a new speech request. New files are saved by content hash in the task delivery folder; existing files and task status are unchanged.
- **Short lines for vertical video.** `--max-chars` (4–80, punctuation excluded) splits long sentences into short lines, preferring breaks after punctuation, quotes, title marks and particles, or before common sentence-starting characters. English words and numbers are never split, including thousands-separated amounts such as 100,000. Split timing is estimated by character share. `--strip-end-punct` removes commas, full stops and similar marks at either end of a line while keeping question marks, exclamation marks and quotes. Both options also work on machine text.
- **Valid reviews only.** Items that are unregistered, edited after registration, missing, based on changed recognition text, or with only punctuation on either side are listed with a reason instead of falling back to machine text, and the rest of the batch still exports. A review matching less than 60% of the recognized characters, usually a rewrite or the wrong item, is not forced onto the timeline.
- **Cues worth a spot check.** `check_cues` lists cues that are mostly corrected, read faster than 12 characters per second, or could only be cut by length, so they can be checked before delivery.
- `export-srt` without the new options produces byte-for-byte the same output as before.

### Upgrading and compatibility

Users on CY-CharmYee 1.6.0 or later can update through the existing updater and install with `update --apply`. All new options are optional; installation arguments, configuration, credentials and task data formats are unchanged, so no migration is needed. Existing tasks that kept recognition segment timing can export reviewed subtitles after registering a review through the existing workflow.

An installation still using the old `dyb-*` or `douyin-brain` brand must run the new installer for its first move to CY-CharmYee; its old updater cannot cross product identities. See [existing-user upgrade guidance](../RELEASING.md#已有用户如何升级) and the [runtime guide (Chinese)](../../references/runtime.md).

### Verification scope

Final local pre-release regression passed **261 behavioral tests in 179.935 seconds** (Python 3.12 with pinned dependencies). During development, an end-to-end CLI export of a 35-second commentary sample with mocked Doubao recognition carried all 8 corrections of names, titles, models, numbers and terms into the subtitles with unchanged timing and a 0.92 match ratio. At 14 characters per line it produced 19 cues, with one cut by length and flagged. Aligning about 15,000 characters took about 3.5 seconds.

After the feature merged, automated code review found that thousands-separated numbers could be split and that a punctuation-only item stopped the whole export. Both are fixed in this release with regression tests. GitHub CI, tag, source commit and public-package verification are recorded in this Release's public verification appendix.

This round made no live Doubao speech requests, did not run the full workflow on a real video, and did not check how the subtitles display after import into JianYing or other editors; split-line timing is an estimate. Real conversations in Agent hosts were not verified either.
