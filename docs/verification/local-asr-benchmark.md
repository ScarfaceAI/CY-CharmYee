# 本地识别正式基准（第一期）

日期：2026-11-17。代码：`main` 的 8294abe，评测时用冻结副本。本地模型：Qwen3-ASR-0.6B int8（sherpa-onnx 2.0.1），CPU 3 线程。对照：豆包录音文件识别极速版。

**结论：不通过，豆包保留。** 五条通过线只过了“静音和纯音乐不出字”这一条。按计划，验收不过就不删豆包，先把差距和选项交给用户决定。

## 素材

- 用户处理过的视频 18 条，计划 19 条，其中 1 条缺音轨与结果的配对。每条都有当时的豆包结果。
  - 7 条有校对稿，参考文本共 1,164 字。
  - 另外 11 条没有校对稿，用于盲评。
- 用户自己的 2 条视频：
  - 第一条取前 500 秒，是中英混杂的英雄联盟产业话题；
  - 第二条整条，74.5 秒。
  - 豆包对照由用户本人运行，合计约 9.6 分钟，没有超过原定的 10 分钟额度。
- 无语音素材共 4 段，各 30～40 秒：数字静音、约 −50 dBFS 白噪声、系统铃声拼接、合成多声部乐曲。
- 素材和逐条结果只留在本机，不进仓库。

## 方法

- **错字率**：最短编辑距离除以参考字数。计分前统一大小写和全半角，去掉标点和空白，可解析的汉字数字统一成阿拉伯数字，常见成语保留原样。
- **独立复算**：7 条校对稿用另一套归一办法重算了一遍，豆包 3.72%、本地 6.48%，相差 1.74 倍，与评测脚本的结果一致。
- **留一法**：测某条校对稿时，纠错记忆和词表只来自其余 6 条，并通过真实的 `register-review` 登记。
- **盲评**：
  - 两边说法不一致的地方，每处随机标成 A 或 B，由 Claude 在不知道来源的情况下逐处判断。依据是上下文和常识，不是听音。
  - 一共 166 处，判定了 134 处；拿不准的 32 处从两边和参考里一起剔除。
  - 参考答案由两边一致的部分加上判定结果拼成。两边错得一模一样的地方查不出来，所以绝对错字率会偏低，但两边的倍数仍可比。
- **消融**：数字转换开和关、热词开和关，各自重算一遍。

## 结果

| 通过线 | 结果 | 结论 |
| --- | --- | --- |
| 1. 本地原始错字率不高于豆包的 1.5 倍 | 7 条校对稿：本地 6.53%，豆包 3.69%，1.77 倍。盲评 13 段：本地 3.39%，豆包 0.78%，4.35 倍 | 不通过 |
| 2. 纠正后，人名、数字、术语的准确率不低于豆包 | 校对稿关键项：本地对 4／24，豆包对 15／24。盲评关键项：本地对 3／18，豆包对 12／18 | 不通过 |
| 3. 静音和纯音乐一个字都不出 | 4 段都是 0 字 | 通过 |
| 4. 纠错改对多于改错 | 改对 0，改错 0 | 不通过 |
| 5. 数字转换、热词各自修好的比改坏的多 | 数字转换：修好 0，改坏 0，另有 8 处只是换了写法。热词：在 7 条校对稿上没有触发复听 | 不通过 |

另外两项统计：

- **疑点清单**：20 处关键错误，一处也没标出来；8 条疑点里没有一条碰到真正的错误。
- **速度**：20 段口播共 1,650.9 秒，处理用时 660.5 秒，实时率 0.40，约是实时的 2.5 倍速。

评测中发现 1 处缺陷：本地识别的一段输出里混进了模型内部标记 `<asr_text>`，出稿前需要清掉。

## 没有覆盖

- 多人长对话、超过 500 秒的长录音、带背景音乐的长片。
- 从 1.8.0 升级、Claude Code 和 Codex 里的真实对话、字幕导入剪映。
